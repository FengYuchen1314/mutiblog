# Halo / Earth / HedgeDoc 产品基线研究

> 研究版本：Halo `v2.25.0`、Earth `v1.17.1`、HedgeDoc `1.11.1`
> 用途：记录可复核的产品与代码研究结论，不构成对旧 MutiBlog 实现的引用。

## 1. 研究边界

- Halo 提供后台信息架构、列表与表单交互、内容状态、主题生命周期的基线。
- Earth 提供默认公开主题的页面结构、视觉和设置项基线。
- HedgeDoc 提供 Markdown 编辑、预览、分栏、全屏和图片粘贴体验基线。
- MutiBlog 不复制 Halo 的 Java/Spring、数据库真相源、插件/RBAC、多用户或 Thymeleaf 运行时。
- MutiBlog 的多语言、文件真相源、静态发布和单管理员规则优先。

## 2. Halo 2.25 后台外壳

Halo 控制台采用 Vue 3、Vue Router、Pinia、TanStack Vue Query、Tailwind CSS。公开包 `@halo-dev/components@2.25.0` 使用 MIT 许可证，可提供按钮、卡片、实体列表、页头、菜单、模态框、分页、状态、标签、提示等基础组件。

经源码与官方演示站点交叉核对，桌面布局为：

- 约 16rem 的固定左侧栏，顶部为品牌与“访问首页”；
- 全局搜索入口，显示 `⌘/Ctrl + K`；
- 菜单按“内容 / 外观 / 系统 / 工具”分组；
- 管理员资料与退出入口固定在底部；
- 主内容区使用浅灰画布、白色卡片和紧凑工具栏；
- 移动端折叠为抽屉式导航。

MutiBlog 保留以下社区版核心入口：

| 分组 | 页面 |
| --- | --- |
| 总览 | 仪表盘 |
| 内容 | 文章、页面、评论、附件、分类、标签、友链 |
| 外观 | 主题、菜单 |
| 系统 | 设置、概览、备份、工具 |
| AI | Provider、翻译任务、语言与字典 |

明确排除用户、角色、插件、应用市场、商城和商业版模块。

## 3. Halo 列表页模式

文章、页面、评论和附件均使用相同的操作语法：

1. 页头提供主要动作和相邻资源快捷入口；
2. 卡片顶部提供复选框、搜索、状态/类型筛选、排序和刷新；
3. 中部为实体行，行尾为上下文菜单；
4. 勾选后进入批量动作模式；
5. 底部提供总数、页码和 20/30/50/100 条每页；
6. 筛选条件进入 URL 查询参数，刷新后可恢复；
7. 进行中的发布/删除任务通过轮询更新状态。

具体观察：

- 文章页提供分类、标签、回收站、新建，支持发布、下线、设置、移入回收站等批量动作。
- 评论页提供关键字、状态、评论者和排序；实体行显示评论者、所属内容、回复数、回复动作与时间。
- 附件页提供上传、分组、关键字、类型和排序；实体行显示预览、文件名、MIME、大小、时间。
- 菜单页是“菜单集合 + 当前菜单项”的双栏管理，菜单项可排序和嵌套。

## 4. Halo 内容编辑与状态

Halo 的文章与页面采用草稿、已发布快照和内容快照分离的思路。编辑页具有：

- 返回/标题区域；
- 修订、预览、保存、设置、发布动作；
- 自动保存与本地缓存；
- 单独的发布/文章设置弹窗；
- 发布、下线、回收站和永久删除操作；
- 图片上传回调。

MutiBlog 沿用操作语义，但将正文编辑器替换为纯 Markdown，并把每次保存落到文件修订记录。第一次实现的状态集合为：

```text
draft -> published -> unpublished
   |          |             |
   +-------> recycled <-----+
```

定时发布保留在数据契约中，完成基础发布链路后实现。

## 5. Halo 主题生命周期

Halo 把“当前主题设置”和“已安装主题管理”分开：当前页包含预览、主题管理、主题信息和按 schema 动态生成的设置分组；管理器负责安装、选择、启用、升级、重载、重置和卸载。

MutiBlog 必须实现相同生命周期，但主题包运行 MutiBlog 自有 React SSR 协议：

- 本地 ZIP 安装；
- 远程 URL 安装；
- manifest/schema 校验；
- 已安装列表与版本信息；
- 预览构建，不影响线上输出；
- 原子启用；
- 设置重载、重置与迁移；
- 升级与回滚；
- 卸载和可选清理配置；
- 文章/页面/分类自定义模板。

## 6. Earth 主题基线

Earth 的核心公开页面包括：首页、文章、页面、分类、标签、分类集合、标签集合、归档、友链和错误页。插件专属的瞬间、图库、文档等页面不进入 MutiBlog 第一阶段核心。

核心布局为：

- 约 4rem 的吸顶导航；
- Logo/站点标题、层级菜单、搜索、明暗主题切换和语言切换；
- 可选 Hero；
- 首页分类过滤；
- 1/2/3 列文章卡片布局；
- 桌面右侧约 18rem 侧栏，小屏隐藏或下移；
- 圆角白色卡片、封面、分类/标签、标题、摘要、日期；
- 页脚包含站点信息、菜单、社交链接和版权。

默认主题设置至少覆盖布局、全局样式、文章、侧栏和页脚五组，并全部使用数据驱动的多语言字段。

## 7. HedgeDoc 编辑器基线

HedgeDoc 使用 CodeMirror，并通过 inline-attachment 处理粘贴/拖入上传。其值得保留的产品行为是：

- 编辑、预览、左右分栏三种模式；
- 全屏与键盘快捷键；
- Markdown 工具栏；
- 编辑区与预览区同步滚动；
- 拖入或粘贴图片后上传，再在光标处插入 Markdown 图片语法；
- 状态栏反馈光标与保存状态。

MutiBlog 使用 CodeMirror 6 独立实现，不复制 HedgeDoc 的多人协作和权限系统。预览与发布必须调用同一套 Markdown 渲染管线，避免编辑器与公开页面不一致。

## 8. 对 MutiBlog 的直接约束

- UI 复刻不等于后端复刻：每个动作最终写入 Markdown/YAML。
- SQLite 被删除后，列表、统计、搜索和评论索引可从文件重建。
- 公开正文不通过 Go 请求时渲染；发布动作产出静态文件。
- 所有公开实体的表单都包含语言状态矩阵。
- 源语言内容可在 AI 完全不可用时发布。
- 主题、备份和附件操作必须有任务状态与失败诊断，不用长请求假装同步完成。
