# 05 · 多语言、URL 与 SEO 规格

---

## 1. Locale 的三种形态

必须严格区分，混用是本模块最常见的 bug 来源。

| 形态 | 例子 | 用在哪 |
|---|---|---|
| **规范形式 (Canonical)** | `zh-CN`、`zh-TW`、`en`、`ja`、`pt-BR` | 配置、Front Matter、metadata.yaml、API、内存索引的 key |
| **URL 形式 (Prefix)** | `zh-cn`、`zh-tw`、`en`、`ja`、`pt-br` | URL 路径、文件名后缀、输出目录 |
| **HTML lang 属性** | `zh-CN`、`en` | `<html lang>`、`hreflang` |

```go
package i18n

// 规范化：任意输入 → 规范形式（语言小写、Script 首字母大写、Region 全大写）
func Canonical(s string) (model.Locale, bool)

// 规范 → URL 前缀（全小写）。若配置里为该 locale 指定了自定义 urlPrefix，用配置的
func (r *Registry) URLPrefix(loc model.Locale) string

// URL 前缀 → 规范。基于 Registry 的反查表，不做算法推导
func (r *Registry) FromPrefix(prefix string) (model.Locale, bool)
```

**`Registry`** 在配置加载时构建，持有：启用的 locale 列表（有序）、`prefix → locale` 映射、`alias → locale` 映射、`country → locale` 映射、默认与源 locale。配置热重载时整体替换（`atomic.Pointer[Registry]`）。

## 2. URL 方案

### 2.1 完整路径表

| 路径 | 说明 |
|---|---|
| `/` | 302 语言跳转，**唯一的动态端点** |
| `/{prefix}/` | 首页 |
| `/{prefix}/page/{n}/` | 首页分页，n ≥ 2 |
| `/{prefix}/posts/{slug}/` | 文章 |
| `/{prefix}/{pageSlug}/` | 独立页面，如 `/en/about/` |
| `/{prefix}/categories/` | 分类总览 |
| `/{prefix}/categories/{slug}/` | 分类页 |
| `/{prefix}/categories/{slug}/page/{n}/` | 分类分页 |
| `/{prefix}/tags/` | 标签总览 |
| `/{prefix}/tags/{slug}/` | 标签页 |
| `/{prefix}/tags/{slug}/page/{n}/` | 标签分页 |
| `/{prefix}/archive/` | 归档索引 |
| `/{prefix}/archive/{year}/` | 年归档 |
| `/{prefix}/archive/{year}/{month}/` | 月归档，month 补零两位 |
| `/{prefix}/links/` | 友链 |
| `/{prefix}/search/` | 搜索页 |
| `/{prefix}/rss.xml` | RSS |
| `/{prefix}/search-index.json` | 搜索索引 |
| `/{prefix}/404.html` | 该语言的 404 |
| `/sitemap.xml` | Sitemap 索引 |
| `/sitemap-{prefix}.xml` | 各语言 Sitemap |
| `/robots.txt` | |
| `/assets/*` | 主题构建产物（带 hash） |
| `/media/*` | 媒体文件 |
| `/admin/*` | 后台 SPA |
| `/api/*` | 后端 API |

**尾斜杠**：所有页面路径**带尾斜杠**，输出为 `<dir>/index.html`。Nginx 配置 `try_files $uri $uri/index.html =404;`，并对无尾斜杠的请求 301 加斜杠。

### 2.2 保留字（slug 不得使用）

```
posts, page, categories, tags, archive, links, search,
rss.xml, sitemap.xml, search-index.json, 404.html,
assets, media, admin, api, _bundles
```

以及所有已启用 locale 的 `urlPrefix`。创建/修改页面 slug 时校验，冲突返回 422。

### 2.3 各语言 slug 可不同

`/zh-cn/posts/my-server/` 与 `/ja/posts/watashi-no-server/` 可以是同一篇文章。语言切换器必须用**目标语言的 slug** 生成链接，这要求渲染任一语言页面时能拿到所有语言的 URL——`PageProps.site.locales[].url` 就是为此存在。

**若目标语言版本不存在**：语言切换器该项指向该语言的**首页**（而非 404），并加 `data-fallback="home"` 供主题样式区分。

## 3. 语言协商（仅作用于 `/`）

### 3.1 算法

```go
func (h *LocaleHandler) Negotiate(r *http.Request) (model.Locale, string /*reason*/) {
    reg := h.registry.Load()

    // 1. Cookie —— 用户显式选择，最高优先级
    if c, err := r.Cookie(reg.CookieName); err == nil {
        if loc, ok := reg.FromPrefixOrCanonical(c.Value); ok && reg.Enabled(loc) {
            return loc, "cookie"
        }
    }

    // 2. Accept-Language
    if loc, ok := h.matchAcceptLanguage(r.Header.Get("Accept-Language")); ok {
        return loc, "accept-language"
    }

    // 3. IP → 国家 → locale
    if cc := h.countryCode(r); cc != "" {
        if loc, ok := reg.CountryLocale(cc); ok && reg.Enabled(loc) {
            return loc, "country:" + cc
        }
    }

    // 4. 默认
    return reg.DefaultLocale, "default"
}
```

### 3.2 Accept-Language 匹配

```go
func (h *LocaleHandler) matchAcceptLanguage(header string) (model.Locale, bool) {
    if header == "" { return "", false }
    tags, qs, err := language.ParseAcceptLanguage(header)   // golang.org/x/text/language
    if err != nil { return "", false }

    // 按 q 值降序（ParseAcceptLanguage 已排序，但要处理 q=0 的排除）
    type cand struct{ tag language.Tag; q float32 }
    var cands []cand
    for i, t := range tags {
        if qs[i] <= 0 { continue }        // q=0 表示明确拒绝
        cands = append(cands, cand{t, qs[i]})
    }

    reg := h.registry.Load()
    for _, c := range cands {
        s := c.tag.String()               // 如 "ja-JP", "zh-Hant-HK", "en-GB"

        // (a) 精确匹配（规范化后）
        if loc, ok := reg.Canonical(s); ok && reg.Enabled(loc) { return loc, true }

        // (b) 别名表匹配（配置的 localeAliases，含中文变体规则）
        if loc, ok := reg.Alias(s); ok && reg.Enabled(loc) { return loc, true }

        // (c) 逐级截断：zh-Hant-HK → zh-Hant → zh；en-GB → en
        for cut := s; ; {
            i := strings.LastIndex(cut, "-")
            if i < 0 { break }
            cut = cut[:i]
            if loc, ok := reg.Canonical(cut); ok && reg.Enabled(loc) { return loc, true }
            if loc, ok := reg.Alias(cut); ok && reg.Enabled(loc) { return loc, true }
        }

        // (d) 同语言不同地区：en-GB 未配置，但启用了 en-US → 匹配 en-US
        base, _ := c.tag.Base()
        if loc, ok := reg.FirstEnabledWithBase(base.String()); ok { return loc, true }
    }
    return "", false
}
```

### 3.3 中文特例（必须完全实现）

`localeAliases` 的默认值必须包含：

| Accept-Language 值 | → |
|---|---|
| `zh`, `zh-Hans`, `zh-CN`, `zh-SG`, `zh-MY`, `zh-Hans-*` | `zh-CN` |
| `zh-Hant`, `zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant-*` | `zh-TW` |

注意 `zh-Hant-HK` 的截断链是 `zh-Hant-HK` → `zh-Hant` → `zh`，若只做朴素截断会掉进 `zh-CN`，**这是错的**。因此别名表必须在截断**之前**先尝试整串与逐级前缀匹配（上面算法的 (b) 在 (c) 之前，且 (c) 每一级都同时查别名表）。

**测试用例（必须全部通过）**：

| Accept-Language | 启用 zh-CN,zh-TW,en,ja | 期望 |
|---|---|---|
| `ja-JP,ja;q=0.9,en;q=0.8` | | `ja` |
| `en-US,en;q=0.9` | | `en` |
| `en-GB` | | `en` |
| `zh-CN,zh;q=0.9` | | `zh-CN` |
| `zh-TW,zh;q=0.9` | | `zh-TW` |
| `zh-HK,zh;q=0.8,en;q=0.5` | | `zh-TW` |
| `zh-Hant-HK` | | `zh-TW` |
| `zh-SG` | | `zh-CN` |
| `zh` | | `zh-CN` |
| `fr-FR,fr;q=0.9` | | 无匹配 → 走 IP |
| `de;q=0` `,en;q=0.5` | | `en`（de 被显式拒绝） |
| `*` | | 无匹配 → 走 IP |
| （空） | | 无匹配 → 走 IP |

### 3.4 IP → 国家

**不内置 GeoIP 数据库**（体积与许可问题）。按优先级读取 header：

```go
func (h *LocaleHandler) countryCode(r *http.Request) string {
    // 仅当请求来自 trustedProxies 时才信任这些 header
    if !h.isTrustedProxy(r.RemoteAddr) { return "" }
    for _, k := range []string{
        "CF-IPCountry",           // Cloudflare
        "X-Vercel-IP-Country",
        "X-Country-Code",         // 通用/自建 Nginx GeoIP2
        "CloudFront-Viewer-Country",
    } {
        if v := r.Header.Get(k); v != "" && v != "XX" && v != "T1" {
            return strings.ToUpper(v)
        }
    }
    return ""
}
```

`XX`（未知）与 `T1`（Tor）视为不可用。

配置 `countryLocaleMap` 未命中的国家 → 落到默认 locale。后台设置页提供该映射表的可视化编辑。

### 3.5 `/` 的响应

```go
func (h *LocaleHandler) ServeRoot(w http.ResponseWriter, r *http.Request) {
    if !h.cfg.I18n.RedirectRoot { /* 直接服务 defaultLocale 首页 */ }

    loc, reason := h.Negotiate(r)
    target := "/" + h.registry.Load().URLPrefix(loc) + "/"

    // 保留 query string
    if r.URL.RawQuery != "" { target += "?" + r.URL.RawQuery }

    w.Header().Set("Cache-Control", "no-store")     // ★ 关键
    w.Header().Set("Vary", "Accept-Language, Cookie")
    w.Header().Set("X-Locale-Reason", reason)        // 调试用，生产可关
    http.Redirect(w, r, target, http.StatusFound)    // 302，不是 301
}
```

**为什么 `no-store` 而不是 `Vary`**：CDN 对 `Vary: Accept-Language` 的处理会产生极高的缓存基数（Accept-Language 值几乎人人不同），实际等于不缓存，还占用缓存空间。直接 `no-store` 更诚实。Cloudflare 上把 `/` 配成 Bypass Cache。

**为什么 302 而不是 301**：301 会被浏览器永久缓存，用户之后切换语言偏好将无法生效。

**这个端点是全站唯一必须经过 Go 的公开路径**，且只有裸访问根域名时命中，QPS 极低。

### 3.6 语言切换

前端 `LocaleSwitcher` island 点击时：

```ts
document.cookie = `preferred_locale=${prefix}; path=/; max-age=31536000; samesite=lax${secure}`;
location.href = targetURL;   // 直接跳到目标语言的对应页面
```

**纯客户端行为，不请求 API**。Cookie 名从 `site.i18n.cookieName` 注入到页面（`window.__BLOG_I18N__`）。

## 4. hreflang 与 SEO

### 4.1 hreflang 生成规则

对每篇文章的每个语言版本页面，`<head>` 中输出：

```html
<link rel="alternate" hreflang="zh-CN" href="https://example.com/zh-cn/posts/my-server/">
<link rel="alternate" hreflang="en"    href="https://example.com/en/posts/my-server/">
<link rel="alternate" hreflang="ja"    href="https://example.com/ja/posts/my-server/">
<link rel="alternate" hreflang="x-default" href="https://example.com/zh-cn/posts/my-server/">
```

规则：
1. **只列出实际存在且已发布的语言版本**。翻译中/失败/未翻译的语言**不得**出现。
2. **必须包含自身**（自引用），这是 Google 的硬性要求。
3. `x-default` 指向 `sourceLocale` 的版本；若源语言版本不存在（罕见），指向 `defaultLocale` 的版本。
4. hreflang 值用**规范形式**（`zh-CN` 而非 `zh-cn`），href 用 URL 形式。
5. **必须双向对称**：A 页面指向 B，B 页面也必须指向 A。这意味着**新增一个语言版本时，其他所有语言版本页面都要重渲染**（见 [docs/04 §2.1 第 10 条](04-render-pipeline.md)）。

对列表页（首页/分类/标签/归档）同样输出 hreflang，指向各语言的对应列表页。

### 4.2 Canonical

每页 `<link rel="canonical">` 指向自身的绝对 URL。分页页面的 canonical 指向**自身**（不是第一页）——现代 SEO 实践。

### 4.3 结构化数据

文章页输出 `BlogPosting`：

```json
{
  "@context": "https://schema.org",
  "@type": "BlogPosting",
  "headline": "我的服务器搭建记录",
  "description": "…",
  "image": ["https://example.com/media/2026/08/cover.png"],
  "datePublished": "2026-08-09T12:00:00+08:00",
  "dateModified": "2026-08-09T13:00:00+08:00",
  "author": { "@type": "Person", "name": "站长", "url": "https://example.com/zh-cn/about/" },
  "publisher": { "@type": "Organization", "name": "My Blog",
                 "logo": { "@type":"ImageObject", "url":"https://example.com/media/logo.png" } },
  "mainEntityOfPage": { "@type": "WebPage", "@id": "https://example.com/zh-cn/posts/my-server/" },
  "inLanguage": "zh-CN",
  "keywords": "Debian, Docker"
}
```

其他页面类型：首页 `WebSite` + `SearchAction`；分类/标签页 `CollectionPage`；面包屑 `BreadcrumbList`。

### 4.4 Sitemap 中的 hreflang

```xml
<url>
  <loc>https://example.com/zh-cn/posts/my-server/</loc>
  <lastmod>2026-08-09T13:00:00+08:00</lastmod>
  <xhtml:link rel="alternate" hreflang="zh-CN" href="https://example.com/zh-cn/posts/my-server/"/>
  <xhtml:link rel="alternate" hreflang="en" href="https://example.com/en/posts/my-server/"/>
  <xhtml:link rel="alternate" hreflang="x-default" href="https://example.com/zh-cn/posts/my-server/"/>
</url>
```

根元素需声明 `xmlns:xhtml="http://www.w3.org/1999/xhtml"`。

## 5. 多语言内容的 fallback 策略

| 场景 | 行为 |
|---|---|
| 访问 `/ja/posts/x/`，日语版本不存在 | 静态文件不存在 → 404（返回 `/ja/404.html`）。**不做服务端 fallback**，因为那需要动态逻辑 |
| 列表页中某文章无当前语言版本 | **不显示**该文章。列表只包含当前语言已发布的版本 |
| 分类/标签名缺少当前语言 | fallback 到 `defaultLocale` 的名称 |
| UI 文案缺少当前语言 | fallback 到 `defaultLocale`，再缺失则输出键名 |
| 菜单项 label 缺少当前语言 | fallback 到 `defaultLocale` |

**设计理由**：前台是纯静态文件，任何"找不到就回退"的逻辑都需要运行时判断，违反 A2/A3。宁可 404。

后台的「多语言」页面会明确列出哪些文章缺少哪些语言版本，引导管理员补齐。

## 6. 404 处理

每个 locale 生成 `<prefix>/404.html`。Nginx：

```nginx
location /zh-cn/ { try_files $uri $uri/index.html /zh-cn/404.html; }
location /en/    { try_files $uri $uri/index.html /en/404.html; }
# 或用 map 动态匹配 locale 前缀
error_page 404 /zh-cn/404.html;   # 兜底
```

Go 自带静态服务时同理：按请求路径首段推断 locale，返回对应 404 页，状态码 404。

## 7. RTL 支持（预留）

`config.i18n.locales[].dir: rtl`（默认 `ltr`）。渲染时 `<html lang="ar" dir="rtl">`。主题 CSS 用逻辑属性（`margin-inline-start` 等）。MVP 不提供 RTL 语言，但**渲染器与主题必须正确透传 `dir` 属性**。

## 8. 后台的多语言管理页

`/admin/i18n/` 提供：

- **语言列表**：启用/禁用、排序、自定义 urlPrefix、设为默认/源语言。禁用某语言时警告"其内容文件不会被删除，但会从站点移除"。
- **翻译矩阵**：文章 × 语言 的表格视图，每格显示状态徽章（original/completed/outdated/failed/missing），支持筛选"所有 outdated"、"所有缺失"，支持批量触发翻译。
- **国家映射表**：`countryLocaleMap` 的可视化编辑。
- **别名表**：`localeAliases` 的可视化编辑，附实时测试框（输入 Accept-Language 字符串，显示协商结果）。
- **UI 文案编辑**：`data/translations/<locale>.yaml` 的键值编辑器，标注缺失键。
