## 2026-08-11 当前结论

### 首次正式镜像发布与安全回滚

- PR #1 已 squash 合并为 `main` 提交 `07286919a657d1dd0e74f6be0f7f06acc5083864`；GitHub Actions CI #16 与 Publish container #1 的 Go、TypeScript、前端、候选容器、多架构推送、SBOM 和 provenance 门禁全部通过。
- VPS 原有 `mutiblog-update.timer` 处于 disabled/inactive，应用仍运行六小时前的 `mutiblog:staging`。部署文件先按提交号备份，再与仓库哈希逐项对齐；定时器已设为 enable，但在本轮人工更新成功前不启动周期触发。
- 首次拉取正式 `latest` 后，候选容器以正确提交版本启动，但既有站点的启动静态重建失败：Node 权限模型只得到尚不存在的输出目录本身，没有得到其未来子树权限，报错 `Use --allow-fs-write to manage permissions`。
- 更新器没有接受该候选，自动恢复 `mutiblog:rollback`；旧容器恢复健康，上一成功 release 与公网文章未被替换。这为 A23 的失败不替换当前健康镜像提供了一次真实 VPS 证据。
- 修复保持 Node 权限模型开启，只增加精确的 `<output>/*` 子树写权限；同时把“初始化数据卷后重启并完成静态重建”加入分支 CI 与发布工作流的容器冒烟，避免未初始化健康检查漏掉相同问题。修复镜像尚待 CI、重新发布和 VPS 公网复测。

- `https://mutiblog.nl.chrono-well.top/` 可从公网访问，并按规则跳转到 `/zh-CN/`；静态首页、导航、中英文入口和已发布文章均可读取。
- `/console/` 可从公网加载，现有会话下控制台没有浏览器错误；运行状态显示索引 `ready · 2`、发布器 `idle`。
- 公网控制台延迟等待异步请求后可读取 `hello-world` 的中英文当前版本、已批准动态评论、Earth `v1.0.0` 和三条已成功 DeepSeek 翻译任务；文章列表与公开静态 release 的实体一致。
- 当前线上仍是上一批验收镜像：公开站存在一篇文章，而旧控制台仪表盘文章数显示为 `0`。本地未发布修复已改为真实统计，但在新镜像通过 VPS 门禁前不得把这一项记为已上线。

- 本轮没有在本机启动服务、构建或执行测试；当前执行环境阻止 SSH 出站，因此以下未发布修复仍须等待 VPS 容器构建和公网回归，不能仅凭源码检查改为“通过”。

## 当前未发布修复

- 仪表盘文章、页面、评论数量改为读取真实 API 总数；未实现浏览量统计时显示 `—`，不再伪造为 0。
- 仪表盘“创建文章/页面”直接进入对应编辑器，“设置”进入真实设置页。
- 内容、评论、修订、翻译任务、来源和索引状态按后台语言显示，不再暴露内部英文枚举。
- `概览`显示真实运行时与索引状态；`工具`支持索引检查、索引重建和带原子发布门禁的公开站重建，不再使用空资源占位页。
- 全局搜索入口跳转到真实索引检查工具。
- 编辑器页头预览会切换到当前未保存草稿的 Markdown 预览；不再是无事件按钮。
- 文章和页面的新建、编辑链路完整保存每种语言的 SEO 标题与 SEO 描述；保存失败时发布动作会停止，不会错误发布旧修订。
- 文章和页面列表的搜索、状态、语言与排序控件已绑定真实数据；附件列表支持真实关键字、文件类型和排序筛选，不再是装饰性控件。
- 公开静态搜索索引同时收录文章和页面；每种语言的 Earth 404 页面由主题外壳生成，Go 静态服务会以真实 HTTP 404 状态返回该页面。
- 自定义主题渲染进程启用 Node 权限模型，只读本次构建快照与主题目录、只写 staging 输出，并默认禁止网络、子进程、Worker 和原生扩展，避免主题读取服务器本地 API Key。
- 主题支持上传 ZIP 和公网 HTTPS URL 两种安装入口；远程下载带 SSRF 地址过滤、重定向/超时/体积限制，并复用活动主题升级的构建回滚事务。
- API 业务错误和网络中断统一经过当前后台语言字典；初始化字段不再显示后端英文校验句子，错误代码与字段结构仍保留供精确逻辑判断。
- 控制台静态资源分包和 Caddy 缓存策略等待 VPS 构建验证后发布。
- 文章与页面列表新增 URL 可恢复筛选、本页选择、跨页批量回收/恢复/永久删除和分页；会话失效会带原地址返回登录页。
- Markdown 编辑器补齐标题、粗体、斜体、引用、行内代码和链接源码工具，并支持 `Mod-B`、`Mod-I`、`Mod-K`；仍保持纯 Markdown，不引入富文本状态。尚待 VPS 浏览器验收光标与快捷键行为。
- 分类、标签、友链和菜单保存后自动经过静态构建门禁；失败保留上一版并显示全局警告。发布器状态改为真实 `building / idle / error`。

- 多菜单不再隐式永远使用创建最早的一项；站点设置可选择主导航，构建快照和所有主题上下文统一使用该选择。

- 公开评论列表改为显式字段白名单，只返回评论 ID、父级、公开作者名/网站、正文、语言与时间；永久 YAML 中的 schema、主题引用、审核状态以及邮箱/IP/User-Agent 摘要不会依赖结构体默认序列化规则。该响应契约尚待 VPS 公网回归。
- 语言设置的持久化与静态重建结果在控制台中分开反馈：配置已保存但重建失败时明确提示上一公开 release 仍在线，不再误报为“语言配置保存失败”。该故障路径尚待 VPS 浏览器验收。
- 备份创建遇到永久数据树中的符号链接或特殊文件时改为显式失败，不再静默跳过后仍产出看似完整的归档；秘密文件和事务私有目录的既定排除规则保持不变。该损坏数据树用例尚待 VPS 执行。
- 批量翻译出现部分成功、部分失败或需复核时，只要至少一个目标语言已安全写入，就仍会执行一次静态构建门禁，使成功译文可以上线；任务最终状态继续保留整批失败或需复核，不会伪装成全部成功。该混合结果与失败重建路径尚待 VPS 执行。
- 文章和页面正文默认按最多 6000 个 Unicode 字符分段翻译，受保护 Markdown 结构跨分段保持；每个目标语言的整批分段增加 15 分钟总时限，超时以 `translation-timeout` 持久化并在控制台本地化显示。该长文、慢响应与超时恢复路径尚待 VPS 执行。
- 分段译文拼接不再对每段执行 `TrimSpace`：只移除 Provider 额外包裹的 CR/LF，保留 Markdown 首行缩进、制表符和行尾双空格硬换行；最终占位符恢复也不裁剪全文外层空白。该结构保持用例尚待 VPS 执行。

## 发布门禁

上述“未发布修复”只有同时满足以下条件才可改为通过：

1. VPS 容器内控制台测试、类型检查和生产构建全部通过；
2. Docker 镜像重建并健康启动；
3. 公网重新登录后逐页核对中英文状态文案、真实统计、概览、工具和文章编辑器；
4. `/console/` 与 API 使用 `no-store`，带哈希的控制台资源使用 immutable，公开 HTML 保持协商缓存；
5. 失败时不替换当前健康镜像和静态 release。
